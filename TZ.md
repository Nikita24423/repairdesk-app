# Краткое техническое задание
## Система аналитики заявок на ремонт производственного оборудования (RepairDesk)

### 1. Назначение
Веб-приложение для учёта заявок на ремонт оборудования и оценки эффективности их выполнения: соблюдение SLA, среднее время ремонта (MTTR), backlog, нагрузка мастеров.

### 2. Пользователи и роли
| Роль | Права |
|------|--------|
| Администратор | Полный доступ: заявки, оборудование, аналитика, пользователи |
| Диспетчер | Создание и редактирование заявок, назначение мастеров, оборудование, аналитика |
| Мастер | Просмотр и ведение назначенных себе заявок (статус, комментарий о работах), своя аналитика |

### 3. Основные сущности
- **Пользователь** — имя, email, пароль, роль
- **Оборудование** — название, инвентарный номер, цех, тип
- **Заявка на ремонт** — заголовок, описание, оборудование, приоритет, статус, создатель, исполнитель (мастер), SLA (часы), даты создания / назначения / начала / завершения, комментарий о работах

**Статусы:** новая, назначена, в работе, выполнена, отменена.  
**Приоритеты:** низкий, средний, высокий, критический.

### 4. Функциональные требования
1. Аутентификация по email и паролю.
2. CRUD заявок с учётом ролей; фильтры по статусу, приоритету, мастеру, цеху, периоду.
3. Справочник оборудования (админ / диспетчер).
4. Управление пользователями и ролями (только админ).
5. Дашборд KPI: соблюдение SLA, MTTR, backlog, доля выполненных.
6. Аналитика: динамика по месяцам, распределение по статусам/приоритетам, топ оборудования, нагрузка мастеров, нарушения SLA.
7. Сохранение данных в PostgreSQL между сессиями.

### 5. Метрики
- **SLA compliance** — доля выполненных заявок, у которых время от создания до завершения ≤ SLA.
- **MTTR** — среднее время от начала работ (или создания) до завершения.
- **Completion rate** — выполнено / создано за период.
- **Backlog** — заявки не в статусах «выполнена» и «отменена».

### 6. Ограничения MVP
- Без мобильного нативного клиента и push-уведомлений.
- Без интеграции с внешними MES/ERP.
- Без сложного workflow согласований и вложений файлов.

### 7. Стек
Next.js (App Router), TypeScript, Tailwind CSS, Auth.js, Drizzle ORM, PostgreSQL (Neon / Vercel Postgres), Recharts, деплой на Vercel.

### 8. Критерии приёмки
1. Вход под ролями admin / dispatcher / master с разными правами.
2. Создание, просмотр, смена статуса и назначение заявок работают и сохраняются в БД.
3. Дашборд и аналитика показывают согласованные KPI по фильтру периода.
4. Приложение доступно по URL на Vercel.
